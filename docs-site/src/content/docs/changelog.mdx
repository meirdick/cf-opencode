## 0.4.0 (not released)

After `cf-opencode upgrade`, run `cf-opencode rebuild <workspace>` for each older workspace. A rebuild puts `cf-opencode-job` and `cf-opencode-store` on its disk.

Start a task:

- `run --branch`, `--auto`, `--new` and `--worktree`. See [Hand off a task](/guides/hand-off-a-task/).
- One task at a time uses the checkout of a workspace. A second `run` fails with the two fixes: `--new` and `--worktree`.
- `tasks <ses_…> --pull` fetches the task's branch into the local checkout.
- MCP: `handoff_task` takes `branch`, `auto`, `newWorkspace` and `worktree`, and there is a new tool, `pull_task`. A2A: `metadata.auto` and `metadata.worktree`.

Work that a task leaves in the workspace:

- A task that ends with commits that are not pushed or processes left running gets one automatic reply. The task stays `running` until that turn ends. The setting `autoReply` turns it off.
- `cf-opencode-job` in the workspace runs a long command apart from the agent's turn. A running job keeps the workspace awake up to its `--max-minutes`. See [The workspace image](/reference/image/).

Files:

- `cf-opencode cp` copies a file or a folder between workspaces, or between a workspace and this machine.
- The store, an optional R2 bucket (`store: true`): `cp` with `store:<name>`, `cf-opencode store`, and `cf-opencode-store` in a workspace.

The Worker URL:

- `init --domain <hostname>` puts the Worker on a Custom Domain.
- `init --url` repairs an install after the Worker URL changed. `doctor` prints that fix when the URL does not answer.

## 0.3.0 (2026-11-16)

Fixes from a first long run of handed-off tasks with the laptop closed.

After `cf-opencode upgrade`, run `cf-opencode rebuild <workspace>` for each workspace made before 0.3.0. A rebuild puts Node, mise and the browser fix on its disk.

Tasks:

- The result record has `unpushed` and `processes`. A task can end `done` with commits that are only in the workspace, or with a process that the next pause stops. `cf-opencode tasks` shows `done !` for such a task. `tasks <ses_…>` shows the facts and the `--reply` command that tells the agent to finish. See [Work that is not safe](/guides/hand-off-a-task/#work-that-is-not-safe).
- The instruction that `run` adds to each task tells the agent to push work that is not complete, and not to end its turn while a process that it started still runs. See [Long jobs](/guides/hand-off-a-task/#long-jobs).
- `commits` and `changedFiles` do not count what a merge or a new branch brings from the remote.

The workspace image:

- Node 22 is installed. `mise` is installed for a project that pins another version: run `mise trust && mise install`. See [The workspace image](/reference/image/).
- `cf-opencode-browse` works from the workspace with Python's `websocket` module. Before, the Worker refused the connection with HTTP 403.
- `cf-opencode-fetch` takes its options before or after the URL. Before, an option after the URL was ignored.
- `PORT` is not in the environment of the tools that the agent runs.

The CLI:

- The preflight failure of `run` names the local checkout and its path. The check reads your machine, not the workspace.
- `cf-opencode ssh`, `ssh-config` and `preview` set `ConnectTimeout 120`. Before, the first connection to a paused workspace could stop with `Connection timed out during banner exchange`. Replace a Host block that an older `ssh-config` printed.
- `connect` and `run` refuse a session ID in the place of a workspace ID.
- A dropped connection from your machine does not read as a lost task. `--wait` and `--follow` try again for 5 minutes, then stop with exit code 3. The `cannot reach` line says that workspaces and their tasks are not affected. See [Troubleshooting](/troubleshooting/).

Docs: [Move a file between workspaces](/guides/hand-off-a-task/#move-a-file-between-workspaces).

## 0.2.2 (2026-11-12)

- Just after a deploy, Cloudflare can answer for some seconds with its own page. The CLI now tries the request again. If it stops, it prints one line with the HTTP status. Before, `connect` could stop with `Failed: <!DOCTYPE html>`.

## 0.2.1 (2026-11-12)

- A workspace that was running when you set the notify URL now sends task results to it. Before, it sent them only after its next restart.
- `changedFiles` in the result of a task lists the files of the commits of the task and its uncommitted changes. It does not list files that changed in the remote.
- `init` and `upgrade` wait for the deployed version before they print the "Worker healthy" line.

## 0.2.0 (2026-11-12)

Hand off tasks, preview dev servers, copy skills, and a tighter Worker.

New:

- `cf-opencode run "<task>"` hands a task to OpenCode in the workspace of the checkout, and returns. A preflight fails on changes that are not committed or pushed (`--allow-dirty` skips it). Flags: `--title`, `--model`, `--skills`, `--schema`, `--wait`, `--follow`, `--timeout`.
- `cf-opencode tasks` lists handed-off tasks across workspaces. The states are `running`, `done`, `failed`, `waiting` and `stopped`. `tasks <ses_…>` shows one task. `--unseen` lists results that you did not read. `--reply "<text>"` sends one more message to a session. The exit codes of `--wait` and `--follow` are 0 done, 1 failed, 2 waiting, 3 timed out, 4 stopped. See [Hand off a task](/guides/hand-off-a-task/).
- The result record: state, summary, and the branch, commits, changed files and pull request that the Worker reads with `git` and `gh pr view` in the workspace. `run --schema <file.json>` adds a checked `structured` value.
- `--follow` shows the agent's tool calls and messages live.
- `cf-opencode notify-url` sets where the Worker sends a task's result, signed with a key from `cf-opencode notify-key`. The URL is the Worker secret `NOTIFY_URL`. Failed deliveries retry after 1, 5 and 30 minutes. `cf-opencode-notify "<text>"` in the workspace sends a note.
- `cf-opencode mcp` is an MCP server over stdio with the tools `handoff_task`, `get_task`, `wait_task` and `list_tasks`. See [Hand off tasks over MCP](/guides/mcp/).
- An A2A endpoint on the Worker, off by default (setting `a2a`). See [Hand off tasks over A2A](/guides/a2a/).
- `cf-opencode skill` prints the handoff skill for agents, and `--install` copies it. `init` installs it for Claude Code and OpenCode when their config folder exists. `--no-skill` skips it.
- `cf-opencode skills` copies skills from your machine into a workspace. `connect --skills` and `run --skills` copy in the same step. `skills default` saves a list for new workspaces. Nothing is copied unless you ask. See [Skills in a workspace](/guides/skills/).
- `cf-opencode preview [workspace] <port...>` opens a dev server of the workspace at `http://localhost:<port>` through an SSH forward. `--web` uses a Worker URL behind a one-time sign-in link. `--public` makes a public URL, `--stop` removes it and `--list` lists them. See [Preview a dev server](/guides/preview/).
- `cf-opencode completion <bash|zsh|fish>` prints a tab-completion script.
- `cf-opencode-search` and `cf-opencode-fetch` in the workspace search the web and read pages through the bindings of the Worker. The setting `searchProvider` defaults to `exa`.
- `cf-opencode-preview <port>` in the workspace prints the preview URL. The remote browser opens a dev server as `http://p<port>.preview.internal/`.
- A session knows where it is. The workspace notes say that the workspace is a clone of the remote. A handed-off session gets a Handoff block before the task. See [What the agent knows](/concepts/what-the-agent-knows/).

### Security in 0.2.0

This release was audited before it shipped. It hardens these areas:

- Access checks on the new preview, task and agent-protocol routes.
- How the CLI shows text from a workspace in your terminal and in tab completion.
- The signature on notifications, and limits on what a workspace can send.
- Outbound requests that carry a credential.
- The notify URL is a secret.

## 0.1.1 (2026-11-12)

- `cf-opencode-search` in the workspace: web search through the AI binding and AI Gateway of the account. No key. The setting `searchProvider` selects the provider. The default is `exa`.
- `cf-opencode-fetch` in the workspace: a page as Markdown, links, HTML, a screenshot or a PDF, through the Browser Run binding.
- The image has the Python `websocket` module.

### Security in 0.1.1

This release hardens the install. If you run 0.1.0, upgrade.

- The Worker checks authentication earlier. A request without valid credentials gets one uniform answer.
- The workspace image build verifies what it downloads.
- Browser sessions and SSH keys are tied to their workspace.
- The terminal and browser routes refuse requests from other websites.
- `lockdown` also covers page reads.

## 0.1.0 (2026-11-12)

First release. It has one package, `cf-opencode`: the CLI. It carries the Worker source and the workspace image. It deploys them to your Cloudflare account with `cf-opencode init`.

What works:

- Workspaces on Cloudflare Containers. They pause to a snapshot when idle and restore on connect.
- Models through the AI binding of your account and AI Gateway. Browsing through the Browser Run binding. No keys.
- `shell`, `ssh` and `ssh-config` over the Worker. No open port.
- GitHub access with a token that stays in the Worker. `init` sets it up once from the `gh` login of the machine.
- `connect --continue` and `connect --session` open a session in the workspace. `sessions` lists sessions across workspaces.
- `rebuild` moves a workspace to the deployed image. Snapshots refresh before they expire.

Known limits are on the [Limits and costs](/limits/) page.
